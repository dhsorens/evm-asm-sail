# Work — contribute a slice

You are a **worker** session for this repo. Execute one coherent contribution
toward SpecRef ↔ `Evm` equivalence, then leave coverage artifacts honest.

Do **not** reimplement rituals here — load and follow the skills below.

## Goal selection

**If the user passed a goal** (text after `/work`, e.g. `/work MUL`,
`/work BinopFamily`, `/work relation for memory`): that is the goal. Clarify
only if it is ambiguous between two deliverables.

**If no goal was given** (bare `/work` / “do what’s next”):

1. Read `PROGRESS.md` (current milestone and next checkbox).
2. Read `docs/opcode-coverage.md` (statuses — source of truth).
3. Take the same default as the coverage UI’s **“Suggested next vertical slice”**
   (canvas + `docs/index.html`, generated by
   `scripts/refresh-proof-coverage-canvas.py` → `next_slice`):
   - Prefer the first **unstated** ALU-family **binop** in order
     `MUL`, `SUB`, `DIV`, `SDIV`, `MOD`, `SMOD`, then other ALU binops.
   - If that class is exhausted, follow `PROGRESS.md` M1/M2
     (e.g. `BinopFamily`, then PUSHn / DUPn / MLOAD / JUMPI / SLOAD / RETURN).
4. Announce the chosen goal in one sentence before coding
   (“Next slice: MUL (`iMul` ↔ `execute_mul`), full `StepResultRel`”).

Do not invent progress from chat or stale HTML alone — if HTML and markdown
disagree, **markdown wins**; regenerate later via `coverage-hygiene`.

## Orient (always)

Before editing Lean:

1. `AGENTS.md` — standing rules (no axioms, no upstream edits, coverage doctrine).
2. Skill `evm-spec-comparison` — if the goal touches relations, observation
   boundary, or a new shape class.
3. Skill `evm-bridge-gotchas` — if proving / debugging a simulation lemma.
4. Relevant mismatch entries in `docs/mismatches.md` and
   `EvmAsmSail/Assumptions.lean`.
5. The archetype file when harvesting: `EvmAsmSail/Opcodes/Add.lean`.

## Dispatch

| Goal kind | Follow |
| --- | --- |
| One opcode / family member with `StepResultRel` | Skill **`opcode-slice`** (full ritual) |
| Shared lemma / relation / representation prerequisite | `evm-spec-comparison` + small scoped Lean change; then coverage rows if status changes |
| Docs / status / site only | Skill **`coverage-hygiene`** only |
| “Plan several next items, don’t code” | Command **`/plan-slice`** instead — stop after planning |

Keep the slice **atomic** (one logical concern). If it balloons, stop after a
compiling subset, run coverage hygiene for what landed, and note the residual
(or suggest `/plan-slice`).

## Execute

1. Implement per the dispatched skill(s).
2. `lake build` — do not continue past errors; no new `axiom`s; no `sorry` for
   `main`.
3. Update living docs as the skills require (`opcode-coverage`, comparison
   matrix, mismatches, `PROGRESS.md` as appropriate).
4. Run skill **`coverage-hygiene`** (refresh script; never hand-edit
   `docs/index.html` / canvas DATA).

## Finish with `/reflect`

After the contribution is done (or cleanly stopped):

1. Summarize in a few bullets: goal, what landed, theorem names, coverage
   status deltas.
2. Run **`/reflect`** (`.claude/commands/reflect.md`). Apply only high-signal
   skill/`AGENTS.md` tweaks; avoid prompt bloat.
3. Do not open follow-up work in the same turn unless the user asks.
